# 产品配方的完整牌号关联

列表中的“配方 N”、详情中的配方卡片/选择器、隐藏重复辅助双链的判断，统一调用 `lib/utils/formula_association.dart` 的纯函数 `linkedFormulasForProduct`。

## 新配方推荐格式

```markdown
---
关联产品: '[[RS1001]] [[RS1002-2B]]'
---
| 原料编号 | 投入数(g) | 备注 |
| --- | --- | --- |
| [[RS1001]] | 60 | |
| [[RS1002-2B]] | 40 | |

> 施工比例：按原始资料填写
```

`关联产品` 必须是 YAML **字符串标量**。多个完整牌号分别使用双链，以空格分隔。不使用对象数组，不把来源路径、聊天记录 ID、客户身份、个人联系方式或价格写入公开字段。

配方标题可以是任意业务名称；混拼、多方案、历史标题与别名场景应显式填此字段，不依赖标题猜测。含多个方案列的同一原料表，仍按表内明确链接的全部产品关联，不更改原始用量或 TDS 参数。

## 确定性规则

1. 产品身份为完整文件名，以及该产品 `实验牌号` 字段中明确确认的完整牌号。首尾空白和大小写不区分；所有数字、字母、连字符、点号后缀保留。不会把 `RS7959-2` 并到 `RS7959`，也不会把 `RD100` 配给 `RD10`。
2. 配方的参与产品为 `关联产品` 字符串中的产品双链，与 Markdown 原料表“原料编号 / 原料名称 / 原料 / 组分”列中产品双链的**并集**。原料表须使用标准的 `|` 表头、分隔行和数据行。
3. 普通正文、独立导航双链、施工说明、备注列、无关表格及围栏代码示例中的引用，不作为参与证据。只接受完整的 RS/RD 产品标识；纯数字不补前缀，不做相邻号、基础号或 RD/RS 自动换算。
4. 支持双链目标中的 `产品列表/` 路径、`.md` 扩展名和显示别名；关联时只比较目标完整牌号。新数据仍推荐示例中的裸完整牌号双链。
5. 只有在配方没有有效显式参与产品时，才回退到旧文件名规则：`<完整牌号>-亮/哑/银/黑/底`，仅移除最后一个已知面漆类型后缀；同名完整牌号也可精确关联。未知标题后缀不猜测，应使用 `关联产品`。
6. 同一配方通过产品名、实验号、元数据、原料表多次命中，只显示一次，按原配方顺序保留，支持已有的多配方下拉选择。

例如正式产品 `RS7965` 的已确认字段可写：

```yaml
实验牌号: "RD910-22"
```

这样 `[[RD910-22]]` 的配方可以显示在 `RS7965` 下，但不会扩展到 `RD910-2`。RD1170 各后缀同理，客户端不内置系列级映射。

## 客户端与数据更新

此字段是兼容现有 Markdown/YAML 分发协议的增量业务元数据，不改变签名、存储或同步协议，也不要求修改 TDS 数值。完整牌号匹配、多产品关联和列表标识由新客户端实现，旧安装包不会仅因更新数据而获得这些修复；需要在审核后更新 App/Web 客户端。本变更不构建、不发布安装包。
